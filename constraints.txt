# Transitive dependency lock for the pipeline host, first written 2026-08-25.
#
# requirements.txt states what we DEPEND ON. This file records what actually
# RESOLVED. Keeping them separate is deliberate: pinning transitives directly
# in requirements.txt would conflate intent with resolution.
#
# Why this exists: pip will not advance a transitive dependency that is already
# installed and still satisfies its range, so the host venv drifts silently and
# is not reproducible from anything in the repo. On 2026-08-24 that had left
# certifi five months stale -- a latent TLS risk against any source rotating to
# a newly cross-signed root.
#
# The lock cuts both ways: it also holds a fix back until someone bumps it. On
# 2026-10-24 it still pinned certifi 2026.7.22, which trusts an emSign root
# whose intermediate CA keys were compromised (GHSA-6q48-6c7w-9gw2), four days
# after the fixed release shipped. scripts/check_vulnerabilities.py now flags
# that on every Pass 1.
#
# Install the host venv with:
#     venv/bin/python -m pip install -r requirements.txt -c constraints.txt
#
# To intentionally move transitives, upgrade them, verify, then regenerate:
#     venv/bin/python -m pip freeze --exclude-editable > constraints.txt
# (--exclude-editable matters: a plain freeze emits comiccaster itself as a
# git+ssh URL pinned to an old SHA, which makes a restore try to re-clone.)
#
# CI's gating Tests job installs with this file (since 2026-10-24), so a green
# PR has tested what the host runs. Until then CI installed unconstrained, as a
# canary for new transitive releases. The cost was that nothing tested the host:
# CI stayed green on patched brotli (#243) and certifi (#247) while the host
# ran the vulnerable versions. The canary still runs, weekly and off the merge
# path, in .github/workflows/dependency-canary.yml. A canary failure that Tests
# does not reproduce means "a new transitive release broke us" -- worth
# investigating before the next refresh. Bumping a direct dependency now means
# bumping it here too, or Tests fails on the conflicting pins.
#
# Verified 2026-08-25: pytest 499 passed; 341/341 regenerated feeds
# byte-identical to production output; APScheduler timezone resolution unchanged.
#
# Removed 2026-10-24: APScheduler (with tzlocal, which only APScheduler needed)
# and requests-toolbelt. Nothing in comiccaster/, scripts/, tests/ or
# run_app.py imports them, so they were attack surface with no use.
